NFL PROP BETTING — R&D IDEATION
2026-06-18

Style guide: each idea follows the rebounds modeling template —
hypothesis → edge mechanism → input data → feature sketch → implementation path.
All ideas lean on data we can actually get free or via existing Odds API tokens.

Free data sources available:
  - The Odds API: NFL player props (rush yds, rec yds, pass yds, TDs, receptions, etc.)
  - ESPN API: box scores, game scores, schedule (free, no key)
  - nfl-data-py (Python nflfastR): play-by-play, EPA, air yards, target share,
    snap counts, pressure rate, coverage type (2012+, all free, no key)
  - Pro Football Reference: historical game logs, splits
  - Existing S3 data: nfl/ game lines in the-odds-api-mt bucket

IDEA 1 — Luck Reversion on QB Passing Yards Props
================================================================================
Hypothesis:
  The existing NFL luck model (nfl_luck_utils.py, nfl_final_model.py) measures
  game-level luck (unexpected points vs score differential). Extend this DOWN to
  the player prop level: after a QB has an abnormally lucky or unlucky game
  (garbage time padding, defensive PI gifts, dropped INTs that saved stats),
  next-week passing yards props are mis-anchored to that output.

Edge mechanism:
  Books reprice props using recent rolling averages. A QB who threw for 380 yards
  partly via 2 garbage time drives has their next-week line inflated — fade OVER.
  A QB who threw 210 yards with 3 drops + 2 dropped INTs against them has their
  line deflated — take OVER.

Inputs:
  - Existing luck score per game (already in nfl_luck_utils.py)
  - The Odds API: QB passing yards props for next game
  - nfl-data-py: cpoe (completion % over expected), pressure rate, wp at snap,
    air yards, garbage time snap flags

Features:
  - prev_luck_score (existing model output)
  - cpoe_last_game (isolates QB skill vs luck)
  - garbage_time_yards_pct (% of yards after wp < 0.15)
  - drop_adjusted_yards (actual yards + yards lost on drops)
  - prop_line_delta_vs_season_avg (how much book moved from baseline)

Implementation:
  1. Pull nfl-data-py play-by-play for 2022-25 seasons
  2. Compute per-game luck-adjusted passing stats
  3. Backtest: regress next-game actual yards ~ luck_score + prop_line
  4. If luck_score coefficient is significant, build daily edge scorer
  5. Daily: fetch next game QB props from Odds API, score against model

Closest analog in repo: nfl_final_model.py (spread reversion) + rebounds scoring

IDEA 2 — Air Yards Debt: WR Receiving Yards Props
================================================================================
Hypothesis:
  "Air yards debt" = a WR who receives high intended air yards (deep targets)
  but posts low actual receiving yards (QB overthrows, drops, tight coverage).
  Books anchor next-week props to ACTUAL yards. The debt creates a
  regression-to-opportunity signal: same route tree, same targets, more likely
  to convert next week.

Edge mechanism:
  WR actual yards << opportunity yards → next-week prop UNDER-priced, take OVER.
  WR actual yards >> opportunity yards (lucky short catches, YAC bonanza) →
  next-week prop OVER-priced, fade OVER.

Inputs:
  - nfl-data-py: air_yards, yards_after_catch, wopr (weighted opportunity rating),
    target_share, adot (avg depth of target)
  - The Odds API: WR receiving yards props

Features:
  - air_yards_debt = intended_air_yards - actual_receiving_yards (rolling 3 games)
  - wopr_last_3 (opportunity share — stable signal)
  - adot_last_3 (depth of target — proxy for scheme intent)
  - prop_line_vs_opportunity_yards (market efficiency gap)

Implementation:
  1. Compute air_yards_debt for all WRs 2022-25 via nfl-data-py
  2. Regress next-game actual yards ~ air_yards_debt + wopr + adot + prop_line
  3. Identify threshold (e.g., debt > 40 yards over 2 games) where edge is largest
  4. Daily pipeline: fetch Odds API WR props, score air yards debt from last game

Note: mirrors rebounds pipeline structure (opportunity metric + prop line → edge).
nfl-data-py air yards data is clean and stable going back to 2016.

IDEA 3 — Post-Garbage-Time Stat Correction on RB Rush Props
================================================================================
Hypothesis:
  RBs who accumulate yards in garbage time (team losing by 14+ in Q4) have
  inflated rushing totals that books anchor to. Next game they face normal game
  script and the prop line is too high.

Edge mechanism:
  Garbage time RB rush yards pad the recent rolling average. When the line opens
  5-10 yards above the non-garbage-time average, fade the OVER.

Inputs:
  - nfl-data-py: wp (win probability) at snap time, rush yards per play
  - The Odds API: RB rushing yards props
  - Existing S3 NFL game lines (to flag implied blowout games)

Features:
  - garbage_time_rush_yds (yards when wp < 0.15)
  - non_garbage_rush_yds (clean yards only)
  - prop_line_vs_non_garbage_avg (the overpricing gap)
  - next_game_script (implied by spread — from existing S3 lines)

Implementation:
  1. Pull nfl-data-py play-by-play, flag garbage time snaps (wp < 0.15)
  2. Split rush yards per game: garbage vs non-garbage
  3. Backtest: non_garbage_avg < prop_line by > N yards → fade OVER
  4. Daily: compute non-garbage avg for each RB, compare to prop lines

IDEA 4 — Target Share Redistribution When WR1 Misses
================================================================================
Hypothesis:
  When a WR1 is ruled out, target share redistributes to WR2 and slot receivers.
  Books zero out the absent WR quickly but are slow to fully price in the
  beneficiary uplift — especially for WR3s and TEs who are lower-profile.

Edge mechanism:
  Target share is roughly conserved (team passes ~N times per game regardless of
  personnel). WR1 miss = 7-9 target redistribution. Identify who absorbs them
  based on route participation + historical role.

Inputs:
  - nfl-data-py: target_share, route_participation, snap_count per player
  - ESPN injury report API (free): practice participation designations
  - The Odds API: all WR + TE receiving yards and receptions props per game

Features:
  - wr1_out_flag
  - beneficiary_target_share_when_wr1_out (historical, same team)
  - route_participation_pct (proxy for target opportunity floor)
  - prop_line_vs_implied_target_uplift

Implementation:
  1. Build WR1-out game log (2021-25): flag games where WR1 DNP
  2. Measure actual target redistribution for each beneficiary vs baseline
  3. Rank beneficiaries by "absorber score" (consistency of WR1-out uplift)
  4. Daily: check injury reports, flag WR1 DNPs, score beneficiary props

IDEA 5 — Divisional Familiarity Decay: QB Efficiency in 2nd Meeting
================================================================================
Hypothesis:
  Same concept as NCAAB fade-revenge applied to NFL divisional rematches.
  When two division teams meet a 2nd time in a season, defensive coordinators
  have extra tape. QB passing efficiency drops systematically — especially for
  scheme-dependent QBs (high CPOE variance means they rely on surprise timing).

Edge mechanism:
  2nd divisional game: DC has 1 full game of film + 2 practices specifically
  targeting this QB's tendencies. Completion % and YPA decline; yards prop
  anchored to 1st-game output is too high.

Inputs:
  - nfl-data-py: schedule (opponent + week), QB cpoe, YPA, completion %
  - The Odds API: QB passing yards + completions props
  - Existing S3 NFL game lines (opponent lookup)

Features:
  - game_number_vs_opponent (1st or 2nd meeting this season)
  - week_of_season (late-season DC prep quality higher)
  - qb_scheme_dependency (CPOE variance across games — high = scheme-reliant)
  - first_meeting_yards (anchor from prior matchup)

Implementation:
  1. Build opponent-meeting lookup from nfl-data-py schedules
  2. Compute QB performance delta (2nd meeting vs 1st meeting, same opponent)
  3. Segment by QB type (scheme-dependent vs gunslinger)
  4. Backtest: 2nd_meeting_flag → fade OVER on QB passing yards

IDEA 6 — Weather-Adjusted Passing Volume Props
================================================================================
Hypothesis:
  High wind (>15 mph) and heavy precip suppress passing volume ~30-40 yards
  per game. Books partially adjust but lag — especially early-week lines before
  game-day weather is confirmed. Early fade OVER at pre-weather-confirmation
  prices has edge.

Edge mechanism:
  Wind > 15 mph → expected passing yards drops ~30-40 yards vs calm baseline.
  Line on Monday/Tuesday doesn't reflect Thursday-confirmed weather. The gap
  between stale line and weather-adjusted expectation is the edge.

Inputs:
  - Open-Meteo (free, no key): historical and forecast wind speed + precip
    by stadium GPS coordinates at kickoff time
  - The Odds API: QB passing yards + game totals (track line movement)
  - Existing S3 NFL game lines

Features:
  - wind_mph_at_kickoff
  - precip_probability
  - dome_stadium_flag (weather irrelevant)
  - prop_line_open_vs_current (has book already adjusted?)
  - qb_season_avg_pass_yds (baseline)

Implementation:
  1. Map all 32 NFL stadiums to GPS coords
  2. Pull Open-Meteo historical data for game dates 2021-25
  3. Fit: actual_yards ~ wind_mph + precip + dome_flag + season_avg
  4. Daily: fetch 48h-out weather, score against Monday opening lines
  5. Signal strength = (model_expected - prop_line) after weather adjustment

IDEA 7 — Snap Count Volatility Pricing Gap for Committee RBs
================================================================================
Hypothesis:
  Books model RB rushing yards as: carry_estimate × YPC. In committee backfields,
  carry allocation is volatile. Players with high snap% variance are mispriced —
  the line anchors to their mean, but fat-tailed actual outcomes create edge when
  we can identify the DIRECTION of this week's allocation from game script signals.

Edge mechanism:
  Committee RB had a low-snap game due to game script (not injury). Next game,
  same role but props anchor to low output. If game script implies a run-heavy
  game (tight spread + low total), bet OVER on the committee RB with low recent carries.

Inputs:
  - nfl-data-py: snap counts, carries per game, RB depth chart role
  - The Odds API: RB rushing yards + attempts props
  - Existing S3 NFL game lines (spread + total for game script)

Features:
  - snap_pct_delta (last_game vs season_avg)
  - role_volatility_score (SD of snap% / mean snap%)
  - prev_game_script (was last game a blowout suppressing carries?)
  - this_game_implied_script (from spread + total)

Implementation:
  1. Pull nfl-data-py snap counts + carry splits 2021-25
  2. Classify RBs by role volatility (SD/mean snap%)
  3. High-volatility RBs: carry model from game script signals
  4. Backtest: low_snap_flag + run_heavy_script_implied → OVER rush yards

IDEA 8 — Post-Big-Game WR Shadow Coverage Fade
================================================================================
Hypothesis:
  After a WR has a breakout game (150+ yards or 10+ targets), next-week defensive
  coordinators shadow them. Books anchor to the big game output. Fade OVER on these
  WRs the following week — the shadow coverage suppresses production.

  Inverse: WR who was shadowed (held to <30 yards) has shadow lifted next week.
  Next-week prop is too low.

Edge mechanism:
  "Breakout game" creates a coverage shift that books don't fully price. The WR's
  prop opens 10-15 yards higher than season average, but performance regresses.

Inputs:
  - nfl-data-py: yards, targets, coverage_type (man/zone)
  - The Odds API: WR receiving yards props
  - Opponent coverage tendency (zone-heavy vs man-heavy — nfl-data-py coverage)

Features:
  - big_game_flag (yards > 130 or targets > 9 last week)
  - target_share_last_game vs career_target_share
  - opponent_coverage_tendency (man% this season)
  - prop_line_delta_vs_season_avg

Implementation:
  1. Identify all "big game" WR performances 2021-25
  2. Compute next-week performance for same WR (post-big-game delta)
  3. Regress: next_week_yards ~ big_game_flag + coverage_type + target_share_delta
  4. Daily: flag prior-week big-game WRs, score coverage matchup for fade signal

IDEA 9 — OL Injury Cascade: Slot WR / TE Props Underprice Short-Route Shift
================================================================================
Hypothesis:
  When a starting OT or OG is ruled out, QB pressure increases. Higher pressure →
  QB throws shorter + quicker. Slot WRs and TEs (short-route specialists) absorb
  more targets; deep outside WRs see fewer. Books reprice QB sack props but are
  slow to cascade this into skill player props.

Edge mechanism:
  OL injury announced Tuesday-Wednesday → books haven't moved WR/TE props by
  Wednesday. Slot WR + TE props are still priced for normal route-depth distribution.
  Take OVER on slot/TE; fade OVER on outside deep WRs.

Inputs:
  - ESPN injury report (free): OL injury designations (out/questionable)
  - nfl-data-py: QB pressure rate, route depth by WR, target share by route type
  - The Odds API: WR/TE receiving props

Features:
  - olt_out_flag (starting OT DNP)
  - qb_pressure_rate_uplift (historical: how much does pressure increase when OT out)
  - wr_route_profile (short/slot vs deep/outside — from adot)
  - prop_line_movement_since_injury_news (has book adjusted already?)

Implementation:
  1. Build OL injury game log 2021-25 (match injury report to starting lineup)
  2. Compute receiver target share shifts vs baseline on OL injury games
  3. Segment by WR route profile
  4. Daily: scrape injury report for OL designations, score slot/TE props

IDEA 10 — QB Rushing Yards: Post-Big-Rush-Game DC Spy Fade
================================================================================
Hypothesis:
  When a scrambling QB has a big rushing game (40+ yards), DCs gameplan to spy
  the QB next week. Books reprice rushing props UP after the big rushing game.
  The correct signal is a FADE — spy + familiarity suppresses rushing yards,
  especially vs opponents with strong edge rush that contains scrambles.

  Inverse: mobile QBs coming off a pocket-bound game (low yards, no design runs)
  are underpriced. Books anchor to the low output, not recognizing the
  game-script-driven suppression.

Inputs:
  - nfl-data-py: QB rushing yards, scramble_flag, designed_run_flag
  - nfl-data-py: edge rusher containment rate (proxy for spy tendency)
  - The Odds API: QB rushing yards props

Features:
  - qb_rush_yds_last_game
  - big_rush_game_flag (>= 40 yards last week)
  - scramble_vs_designed_split (scheme-generated vs opportunistic — matters for spy)
  - opponent_edge_rush_contain_rate
  - prop_line_delta_vs_qb_season_avg_rush

Implementation:
  1. Pull nfl-data-py QB rushing splits (scramble vs design) 2021-25
  2. Compute post-big-rush-game decay by QB type (scramble-heavy vs design-run)
  3. Proxy spy tendency: edge rushers holding contain instead of rushing
  4. Backtest: big_rush_game_flag + high_opponent_contain_rate → fade OVER rush yards
  5. Daily: score next-week QB rushing props against model
