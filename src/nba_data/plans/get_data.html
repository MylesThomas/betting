NBA Unified Data Loader — get_data

Plan · src/nba_data/get_data.py · 2026-05-26

Motivation

Every research script re-implements the same DuckDB + S3 boilerplate to load player game logs and betting odds. There is no shared entry point, no caching, and no way to get a fast data pull without re-scanning raw S3 globs on each run. This plan defines a single get_data() function backed by an S3 parquet cache so any script — research, production, or notebook — gets all three datasets in under a second on warm hits.

Goals

  • Single import: from src.nba_data import get_data — returns logs, props, and game lines together
  • Warm cache (<1 s): reads pre-built parquet files from nba-betting-mt — no raw S3 glob scan
  • Refresh mode: checks manifest timestamp, appends only new raw CSVs, rewrites cache
  • No hidden state: cache metadata is a plain JSON manifest anyone can inspect
  • Works from local dev, Lambda, and Streamlit — same credential chain already in duckdb_s3_creds.py

Cache Manifest Schema

One JSON file written to S3 alongside the parquet files. Tracks provenance and enables append logic.

// s3://nba-betting-mt/data/02_cache/nba_unified/manifest.json
{
  "updated_at": "2026-05-26T18:00:00Z",          // ISO-8601 UTC wall-clock of last cache build
  "seasons": ["2023-24", "2024-25", "2025-26"],   // seasons included
  "max_game_date": "2026-05-25",                // latest GAME_DATE in logs cache
  "max_prop_date": "2026-05-25",                // latest game_time date in props cache
  "row_counts": {
    "player_game_logs": 74812,
    "player_props":     2431087,
    "game_lines":       89543
  }
}

Public API

from src.nba_data import get_data

# Fast path — read from S3 parquet cache (default)
data = get_data()
data.logs    # pd.DataFrame — player game logs, all seasons
data.props   # pd.DataFrame — player prop odds
data.lines   # pd.DataFrame — game lines (spread / moneyline)
data.meta    # dict — manifest contents (updated_at, row_counts, …)

# Refresh: check manifest, append new raw CSVs, rewrite cache
data = get_data(refresh=True)

# Rebuild from scratch (full reload, overwrites cache)
data = get_data(rebuild=True)

# Subset seasons (filter applied post-load, not baked into cache)
data = get_data(seasons=["2024-25", "2025-26"])

# Min-minutes filter (applied after load)
data = get_data(min_minutes=5)
Return type — NBAData is a @dataclass(frozen=True) with fields logs, props, lines, meta.

Runtime Decision Tree

Cold path — cache miss or rebuild=True

DuckDB glob all raw CSVs (both source buckets)
→
Write 3 parquet files + manifest to nba-betting-mt
→
Return DataFrames

Uses the same DuckDB + httpfs pattern as the dispersion script and rebounds builder. Writes parquet with pyarrow via io_utils.

Warm path — cache hit, no refresh flag

Read manifest from S3
→
Read 3 parquet files via io_utils
→
Return DataFrames

Single GetObject per file. Typically <1 second for all three datasets combined.

Refresh path — refresh=True

Read manifest → get max_game_date
→
DuckDB query current season raw CSVs WHERE date > max
→
If new rows: concat + rewrite parquet + update manifest
→
Return DataFrames

Only scans raw CSVs for the current/active season. Past seasons are immutable — they never get new games.

Implementation Steps

1

Write _loaders.py — raw S3 loaders

Extract the DuckDB load patterns from nba_three_point_modeling/99_utils/data_loading.py and the dispersion script into three clean functions: load_logs_raw(seasons, conn), load_props_raw(seasons, conn), load_lines_raw(seasons, conn). Reuse duckdb_s3_creds.py for credential setup. Each returns a pd.DataFrame.

2

Write _cache.py — manifest + parquet I/O

Define S3 cache path constants. Implement read_manifest() → dict | None (None if absent), write_manifest(meta), read_cache() → NBAData, and write_cache(logs, props, lines). Use existing io_utils.py for S3 parquet reads/writes.

3

Write get_data.py — orchestrator

Implements the three paths (cold, warm, refresh) using the decision tree above. Exposes get_data() with the signature shown above. Applies min_minutes and seasons filters post-load — not baked into the cache so it stays general.

4

Write __init__.py

from src.nba_data.get_data import get_data, NBAData — one clean import surface.

5

Build the initial cache

Run python -c "from src.nba_data import get_data; get_data(rebuild=True)" once to populate nba-betting-mt. Log row counts and manifest to verify correctness.

6

Migrate callers (optional, non-breaking)

Replace inline DuckDB boilerplate in the dispersion script and rebounds builder with get_data(). Existing scripts remain unchanged since we are adding, not modifying.

Design Decisions

DecisionChoiceRationale
Cache format Parquet Typed columns, columnar compression — fast to read with pd.read_parquet. CSV has no types; DuckDB file adds another dependency to sync.
Cache location nba-betting-mt Already the internal cache bucket. Keeps raw source buckets read-only.
Refresh granularity Current season only Past seasons are immutable. Only the active season gets new games. Avoids re-scanning all raw CSVs on every refresh call.
Filters in cache? No — raw data cached Cache stores unfiltered data. Callers apply min_minutes, market, season filters post-load. Keeps cache general-purpose for all consumers.
Name + team normalization in cache? Yes — extra columns Joins between the three datasets require it. Logs carry TEAM_ABBREVIATION ("BOS"); lines carry full team names ("Boston Celtics") — you cannot join them without a shared normalized key. Similarly, props player names from the odds API differ in casing and punctuation from NBA API names. player_normalized is added to logs + props; team_normalized is added to logs (maps abbr → full name via team_normalization.py), and lines already use full names. Raw names are kept alongside for debuggability. Both normalization modules (name_normalization.py, team_normalization.py) already exist and are stable.
Warm path read method boto3 / io_utils Cache parquet is a single object per dataset — no glob needed. DuckDB startup overhead is unnecessary on warm reads.

Example: Full Research DataFrame (all 3 seasons)

The canonical starting point for prop modeling — every player-game over 3 seasons with actual stats, their team's closing spread, and the market line for each of the three main props. All three datasets are used, and the joins show exactly what keys connect them. 

from src.nba_data import get_data
import pandas as pd

# ── 1. load everything — warm cache hit is <1s ──────────────────────────────
data = get_data(seasons=["2023-24", "2024-25", "2025-26"])
# data.logs  → ~75k player-games
# data.props → ~2.4M prop rows (one row per player × market × bookmaker × game)
# data.lines → ~90k line rows  (one row per team × market × bookmaker × game)

# ── 2. median spread per game, one row per game ──────────────────────────────
#    logs.team_normalized is the full team name — same space as lines.home_team
spread = (
    data.lines
    .query("market == 'spreads'")
    .groupby(["home_team", "away_team", "game_time"], as_index=False)
    .agg(spread_home=("home_line", "median"))
)
spread["GAME_DATE"] = pd.to_datetime(spread["game_time"]).dt.date

logs = data.logs.merge(
    spread,
    left_on=["home_team_normalized", "away_team_normalized", "GAME_DATE"],
    right_on=["home_team",            "away_team",            "GAME_DATE"],
    how="left",
)
# spread_signed: negative = player's team is favourite
logs["spread_signed"] = logs.apply(
    lambda r: r["spread_home"] if r["is_home"] else -r["spread_home"], axis=1
)

# ── 3. median prop line per player × market × game, pivot to columns ─────────
#    props.player_normalized is already in the same space as logs.player_normalized
props_median = (
    data.props
    .query("market in ('player_points', 'player_rebounds', 'player_assists')")
    .groupby(["player_normalized", "game_time", "market"], as_index=False)
    .agg(prop_line=("prop_line", "median"))
    .pivot_table(index=["player_normalized", "game_time"], columns="market", values="prop_line")
    .rename(columns={
        "player_points":   "line_pts",
        "player_rebounds": "line_reb",
        "player_assists":  "line_ast",
    })
    .reset_index()
)
props_median["GAME_DATE"] = pd.to_datetime(props_median["game_time"]).dt.date

# ── 4. join props onto logs — normalized keys match, no ad-hoc cleaning ──────
df = logs.merge(
    props_median[["player_normalized", "GAME_DATE", "line_pts", "line_reb", "line_ast"]],
    on=["player_normalized", "GAME_DATE"],
    how="left",
)

# ── 6. result ────────────────────────────────────────────────────────────────
KEEP = [
    "season", "GAME_DATE", "PLAYER_NAME", "TEAM_ABBREVIATION", "MATCHUP", "WL",
    "MIN", "PTS", "REB", "AST",
    "spread_signed",                   # team's spread going in (+fav / -dog)
    "line_pts", "line_reb", "line_ast",  # market prop lines for this game
]
df = df[KEEP].sort_values(["season", "GAME_DATE", "PLAYER_NAME"]).reset_index(drop=True)

print(df.shape)         # e.g. (68_412, 15) — only rows with a prop market line
print(df.head(3).to_string())

Open Questions

  • Single merged parquet vs one file per season? Single file is simpler for now — revisit if parquet files become large (>500 MB).
  • Should get_data() print cache age to stdout by default? Useful in notebooks for catching stale data.
  • Add python -m src.nba_data rebuild CLI entry point so Lambda or cron can trigger a rebuild without a caller script?
  • Streamlit Cloud credential path: IAM role on the container — same boto3 chain, should work without changes.
