Step 4 — P(over) Bootstrap + Edge Computation  2026-07-03 ~15:50 ET

Bootstrap Methodology (corrected from v1)

  • mean_adj = line + (1 − 0.25) × (yhat − line) — shrink prediction toward the line
  • simulated_K = mean_adj + sampled_residual (N=10,000 draws)
  • p_model = fraction of simulations where simulated_K > line
  • p_mkt = novig_over (per-book, per-line, correctly computed from decimal odds)
  • edge = p_model − p_mkt
Two bootstrap bugs found and fixed in v2:
  1. TimeSeriesSplit zero-pred rows: The first ~1,343 spine rows (16.7% of training set) were never in a validation fold → oof_pred defaulted to 0 → catastrophically wrong P(over) estimates (p_model ≈ 0.01–0.12 for all bets). Fixed by replacing zero-pred rows with full-model predictions (in-sample, mild lookahead for those rows only).
  2. Biased residuals: Full residual set (including zero-pred rows) had mean=0.885 because zero-pred residuals = actual K count, not prediction error. Using these in bootstrap inflated every p_model upward → 92% of bets showed OVER edge → -7% ROI. Fixed by using only the 6,690 clean non-zero-pred residuals (mean=0.052, std=2.149).

Bug Found: Consensus vs Per-Book Scoring  2026-07-05

Issue: The live pipeline was aggregating all books to a single consensus novig P(over) before scoring, then flagging a play based on that consensus edge. The model was trained at the per-book level — each training row used that specific book's novig as the novig_prob_over feature. The live pipeline violated this: it fed in a cross-book average and produced one edge number, but that number might not exist at any individual book.

Example: Model says P(over 5.5 K) = 55%. Books are priced:
  • DraftKings: novig P(over) = 45% → edge = +10pp (PLAY)
  • FanDuel: novig P(over) = 51% → edge = +4pp (no play)
  • BetMGM: novig P(over) = 53% → edge = +2pp (no play)
Consensus novig = 49.7% → consensus edge = +5.3pp → flagged as WATCH. Neither the right book (DK, +10pp play) nor the right signal (only one book has real edge).

Fix: Score at the per-book level — one row per (player, line, book). Each book's own novig feeds the model, and edge is computed against that book's specific price. Only books that individually meet the threshold are flagged. This matches how the model was trained. Backtest is unaffected (it was already per-book).
