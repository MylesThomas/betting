NBA Rebounds Strategy Dashboard

Plan · Created 2026-05-22 · Owner: Myles Thomas

What We're Building

A new Streamlit page (streamlit_app/pages/3_NBA_Rebounds_Strategy.py) plugged into the existing TQS Props Dashboard at https://tqs-props-dashboard.streamlit.app/. The page shows the full performance history of the production rebounds model — P&L, hit rates, individual plays, and model diagnostics — sourced directly from the scored and settled parquet files in S3.

Primary audience: You (the operator) — daily review of yesterday's bets, running P&L track record, and model health.

Data Sources

S3 Path Pattern Content Used For
s3://nba-betting-mt/rebounds/daily_runs/{date}/{run_id}/
rebounds_scored_settled_{date}.parquet		 Row-level settled bets: player, line, actual REB, result (win/loss/push), pnl_units, strategy_bucket P&L chart, plays table, strategy comparison
…/rebounds_scored_{date}.parquet Today's (unsettled) scored slate: predictions, edges, play flags Today's plays panel — shows what to bet today
…/strategy_summary_{date}.csv Daily rollup by strategy bucket: n_bets, n_win, pnl_units, hit_rate, ROI KPI metrics (fast to load — skip full parquets)
…/run_manifest.json Pipeline run metadata: timestamps, step status, row counts Model freshness indicator, pipeline health

Loading Strategy

Use @st.cache_data(ttl=3600) on S3 reads. On load, enumerate all rebounds/daily_runs/ date prefixes → download strategy_summary_{date}.csv for each → concat into a master DataFrame. Only pull full parquets when the user drills into a specific day or the plays table. This keeps cold-start fast (<5 sec).

Metric Definitions (locked to prod logic)

MetricFormulaSource
Total Bets Count of rows where strategy_bucket != 'neither' settled parquets
Total P&L (units) Sum of pnl_units across all settled bets
Win: american_profit(under_odds) · Loss: -1.0 · Push: 0.0		 settled parquets

ROI per Bet pnl_units / n_bets strategy_summary CSVs

⚠️ Coding Standards — Read Before Writing Any Code

These rules apply to every file in this dashboard. Violating them is a reason to reject the code.

1. Readable names + full type annotations

Every function signature has typed parameters and a return type. Variable names are full words — no df, no tmp, no d.

# BAD
def load(b, p, d=None):
    df = ...
    return df

# GOOD
def load_settled_plays(bucket: str, prefix: str, start_date: str, end_date: str) -> pd.DataFrame:
    settled_plays: pd.DataFrame = ...
    return settled_plays

2. Fail fast — no try/except blocks

Do not catch exceptions. If S3 is unreachable, the boto3 call raises and Streamlit shows an error — that is the correct behavior. Do not swallow errors with except Exception, except KeyError, or any other catch-all. If a precondition isn't met, raise explicitly with a descriptive message.

# BAD
try:
    df = pd.read_parquet(BytesIO(body))
except Exception:
    return pd.DataFrame()

# GOOD
df = pd.read_parquet(BytesIO(body))  # let it raise — caller sees the real error

3. No defensive column checks

Do not write if "REB" in df.columns, df.get("col", default), or .get() on rows unless the column is genuinely optional by design (and documented as such). Trust the schema — if a column is missing, the KeyError tells us something is broken upstream.

# BAD
pnl = row.get("pnl_units", 0.0)

# GOOD
pnl: float = row["pnl_units"]

4. No unnecessary None / empty guards

Do not check if df is None or if len(df) == 0 before every operation. Structure the code so that empty DataFrames are a valid contract and Plotly/Streamlit handles them gracefully. Only guard where the business logic genuinely branches.

5. Constants at module top, not buried inline

S3 bucket names, prefix patterns, column lists, and date literals go in ALL_CAPS constants at the top of the file. No magic strings scattered through functions.

S3_BUCKET = "nba-betting-mt"
DAILY_RUNS_PREFIX = "rebounds/daily_runs"
PLAYED_BUCKETS = {"both", "ols", "xgb"}
PROD_GO_LIVE_DATE = "2025-10-01"  # update when known

6. One responsibility per function

Data loading functions load data. Chart functions build charts. They do not render Streamlit widgets. Keep rebounds_data.py free of any st.* calls — pure data, pure Pandas.

Decisions (answered 2026-05-22)

Question Decision
Q1 — Strategy buckets Two pages:
• Page 1 (default) — "Played Bets": rows where strategy_bucket in (both, ols, xgb). This is the real track record.
• Page 2 — "Blind Unders Benchmark": rows where strategy_bucket = 'neither' — shows what would happen if you blindly bet every under regardless of edge. Useful to see how much value the model filter adds.
Q2 — Date range Default: all-time. Mark the prod go-live date with a vertical annotation on the P&L chart. Sidebar filter presets: All Time / Season-to-Date / Last 30 Days / Last 7 Days + custom date picker.
Q3 — No plays yet today If no scored file exists for today, show a banner: "Model runs daily ~10am ET. Check back for today's plays. Yesterday's results are shown below." Do not surface yesterday's unsettled slate as a proxy.
Q4 — Streamlit Cloud credentials Deferred — test locally first. Will add AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY to Streamlit Cloud secrets after local validation.
Q5 — Unsettled days Exclude from all P&L metrics until settled. Note: unsettled rows are almost always players who didn't play (DNP), not in-progress games. The cumulative P&L chart and KPI strip only count fully settled bets.
Q6 — Charting library Plotly — interactive, cool, great tooltip + zoom UX. Use plotly.express / plotly.graph_objects via st.plotly_chart(use_container_width=True). Altair is the fallback if Plotly adds deployment friction.
