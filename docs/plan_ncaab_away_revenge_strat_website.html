NCAAB Away Revenge Strategy Dashboard

Plan · Created 2026-05-22 · Owner: Myles Thomas

What We're Building

A new Streamlit page (streamlit_app/pages/4_NCAAB_Revenge_Spot.py) plugged into the existing TQS Props Dashboard. The page shows the full season track record of the NCAAB Away Revenge strategy — season W-L, ATS %, P&L, today's plays, and a full plays history table sourced from the daily Lambda's S3 output.

Primary audience: You (the operator) — morning review of today's plays, running season record, and per-game history with prior meeting context.

Strategy in one sentence: When Team A has 0 wins vs Team B this season and is playing them again as the away team, bet Team A (the revenge team) against the spread. Historical edge: 52.6% ATS (n=2,738 games, 6 seasons) for the focal-away segment.

Settlement logic (done in Streamlit)

Unlike rebounds (which has pre-settled parquets), the revenge strategy requires a join of plays CSVs with outcomes CSVs in Streamlit. The data volume is small (<500 plays per season) so this is fast. The join key is (game_date, home_team, away_team). 

# Cover formula (home perspective):
if bet_team == home_team:
    cover = (home_score + spread_home) > away_score
else:                           # bet_team = away team (our case)
    cover = (away_score - spread_home) > home_score   # i.e. away beats spread

# P&L at -110:
pnl = +100/110   # win  (~+0.909u)
pnl = -1.0       # loss
pnl = 0.0        # push (spread == 0; rare)

A play where consensus_spread_home is null has no spread data → mark as result = "no_line" and exclude from P&L / ATS % (still show in table).

Metric Definitions

MetricFormulaNotes
Total Bets Count of rows where bet_team IS NOT NULL and consensus_spread_home IS NOT NULL (i.e. has a line) Excludes no-line plays from all P&L metrics
W-L Win = cover vs consensus spread. Loss = fail to cover. Push = exact spread (count separately, exclude from ATS % denominator) Join plays + outcomes to compute
ATS % wins / (wins + losses) — pushes excluded from denominator Target > 52.4% (break-even at -110)
P&L (units) Win: +100/110 ≈ +0.909u · Loss: -1.0u · Push: 0.0u Standard -110 juice assumption (no actual odds stored for spread bets)
ROI per Bet pnl_units / total_bets Break-even ROI at -110 ≈ -0.045 (need >0 for profitability)
Spread Margin away_score - home_score - spread_away (positive = cover) Shown per row in plays table; helps see near-misses

⚠️ Coding Standards — Same as Rebounds Dashboard

These rules apply to every file in this dashboard.

1. Full type annotations, readable names

# BAD
def load(b, p, d=None):
    df = ...

# GOOD
def load_plays_for_date(bucket: str, prefix: str, game_date: str) -> pd.DataFrame:
    plays_df: pd.DataFrame = ...

2. Fail fast — no try/except blocks

Let boto3 and pandas raise. Streamlit will surface the real error. Do not return empty DataFrames on S3 failure.

3. No defensive column checks

Trust the schema. If consensus_spread_home is missing, that's a pipeline bug — don't silently default to 0.

4. Constants at module top

S3_BUCKET: str = "ncaab-betting-mt"
PLAYS_PREFIX: str = "data/04_output/plays/fade-revenge-spot"
OUTCOMES_PREFIX: str = "data/01_input/historical_game_results"
NCAAB_SEASON_2025_START: str = "2025-11-03"
PROD_GO_LIVE_DATE: str = "2025-11-03"   # update to actual first play date
WIN_PAYOUT: float = 100.0 / 110.0       # -110 juice

5. One responsibility per function

Data module (ncaab_revenge_data.py) is pure data + pandas. No st.* calls. Page file handles all rendering.
